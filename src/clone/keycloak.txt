Using **Keycloak** as an authentication solution for your TikTok clone app built with Express.js and MongoDB is an excellent choice, especially if you want a robust, scalable, and enterprise-grade identity management system. Keycloak is an open-source Identity and Access Management (IAM) tool that supports social logins (Google, Facebook), email/password authentication, and can be extended for custom flows like QR code login. It handles user management, authentication, and token generation out of the box, reducing the need to build these features manually.

Below, I’ll explain how to integrate Keycloak into your app for Google, Facebook, email/password, and QR code authentication, replacing the Passport.js approach from my previous response.

---

### Why Keycloak?
- **Prebuilt Features**: Supports OAuth2, OpenID Connect, social logins, user management, and role-based access control (RBAC).
- **Scalability**: Ideal for apps that might grow to need single sign-on (SSO) or multi-tenancy.
- **Security**: Handles token issuance (JWT), refresh tokens, and session management securely.
- **Customization**: Can be extended for QR code login with custom plugins or workflows.

---

### Step 1: Set Up Keycloak
1. **Install Keycloak**:
   - Download from [Keycloak’s official site](https://www.keycloak.org/downloads) or run via Docker:
     ```bash
     docker run -p 8080:8080 -e KEYCLOAK_ADMIN=admin -e KEYCLOAK_ADMIN_PASSWORD=admin quay.io/keycloak/keycloak:latest start-dev
     ```
   - Access the admin console at `http://localhost:8080` and log in with `admin/admin`.

2. **Create a Realm**:
   - In the Keycloak Admin Console, create a new realm (e.g., `tiktok-clone`).

3. **Create a Client**:
   - Go to "Clients" → "Create".
   - Client ID: `tiktok-clone-app`.
   - Protocol: `openid-connect`.
   - Root URL: `http://localhost:5000` (your Express.js app).
   - Valid Redirect URIs: `http://localhost:5000/api/auth/callback/*`.
   - Save and note the client secret under the "Credentials" tab.

4. **Configure Social Providers**:
   - **Google**:
     - Go to "Identity Providers" → Add "Google".
     - Enter your Google Client ID and Secret (from Google Cloud Console).
   - **Facebook**:
     - Add "Facebook" and input your App ID and Secret (from Facebook Developer Portal).

5. **Email/Password**:
   - Keycloak supports this by default. Enable "User registration" and "Login with email" in the realm settings.

### Step 2: Express.js Integration
#### Install Dependencies
```bash
npm install express mongoose keycloak-connect
```

#### Update `app.js`
```javascript
const express = require('express');
const mongoose = require('mongoose');
const Keycloak = require('keycloak-connect');
require('dotenv').config();

const app = express();
app.use(express.json());

// MongoDB connection
mongoose.connect(process.env.MONGO_URI, { useNewUrlParser: true, useUnifiedTopology: true })
  .then(() => console.log('MongoDB connected'))
  .catch(err => console.log(err));

// Keycloak setup
const keycloak = new Keycloak({}, {
  realm: 'tiktok-clone',
  'auth-server-url': 'http://localhost:8080/',
  'ssl-required': 'external',
  resource: 'tiktok-clone-app',
  credentials: {
    secret: process.env.KEYCLOAK_CLIENT_SECRET // From Keycloak client credentials
  },
  'confidential-port': 0
});

app.use(keycloak.middleware());

// Routes
app.use('/api/auth', require('./routes/authRoutes'));
app.use('/api/videos', keycloak.protect(), require('./routes/videoRoutes')); // Protect video routes

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`Server running on port ${PORT}`));
```

#### Update `.env`
```
MONGO_URI=mongodb://localhost:27017/tiktok_clone
KEYCLOAK_CLIENT_SECRET=your_client_secret
```

### Step 3: Authentication Routes (`routes/authRoutes.js`)
#### Google/Facebook/Email Login
Keycloak handles these via its login page. Redirect users to Keycloak’s login endpoint:
```javascript
const express = require('express');
const router = express.Router();
const keycloak = require('../app').keycloak; // Assuming keycloak is exported from app.js

// Redirect to Keycloak login (includes Google, Facebook, Email options)
router.get('/login', (req, res) => {
  res.redirect('http://localhost:8080/realms/tiktok-clone/protocol/openid-connect/auth?client_id=tiktok-clone-app&redirect_uri=http://localhost:5000/api/auth/callback&response_type=code');
});

// Callback after Keycloak login
router.get('/callback', keycloak.protect(), (req, res) => {
  const token = req.kauth.grant.access_token.token; // JWT from Keycloak
  res.redirect(`yourapp://auth?token=${token}`); // Redirect to mobile app
});

module.exports = router;
```

- Users will see Keycloak’s login page with options for Google, Facebook, or email/password.
- After login, Keycloak redirects to `/api/auth/callback` with an authorization code, which `keycloak-connect` exchanges for a JWT.

#### QR Code Login
Keycloak doesn’t natively support QR code login, but you can extend it with a custom flow:
1. **Generate QR Code**:
   - Use the `qrcode` library to create a QR code with a temporary token.
   - Store this token in MongoDB tied to the user.

2. **Verify QR Code**:
   - When the app scans the QR code, send the token to the backend, which verifies it and requests a Keycloak token.

**Controller** (`controllers/authController.js`):
```javascript
const User = require('../models/User');
const QRCode = require('qrcode');
const jwt = require('jsonwebtoken');
const fetch = require('node-fetch'); // npm install node-fetch

exports.generateQR = async (req, res) => {
  const userId = req.kauth.grant.access_token.content.sub; // Keycloak user ID
  try {
    const user = await User.findOne({ keycloakId: userId });
    if (!user) return res.status(404).json({ message: 'User not found' });

    const qrToken = jwt.sign({ id: user._id }, process.env.JWT_SECRET, { expiresIn: '5m' });
    user.qrCode = qrToken;
    await user.save();

    const qrCodeUrl = await QRCode.toDataURL(qrToken);
    res.json({ qrCodeUrl });
  } catch (error) {
    res.status(500).json({ error: error.message });
  }
};

exports.verifyQR = async (req, res) => {
  const { qrToken } = req.body;
  try {
    const decoded = jwt.verify(qrToken, process.env.JWT_SECRET);
    const user = await User.findById(decoded.id);
    if (!user || user.qrCode !== qrToken) {
      return res.status(401).json({ message: 'Invalid QR code' });
    }
    user.qrCode = null; // Invalidate after use
    await user.save();

    // Exchange Keycloak token
    const response = await fetch('http://localhost:8080/realms/tiktok-clone/protocol/openid-connect/token', {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        grant_type: 'client_credentials',
        client_id: 'tiktok-clone-app',
        client_secret: process.env.KEYCLOAK_CLIENT_SECRET
      })
    });
    const data = await response.json();
    res.json({ token: data.access_token });
  } catch (error) {
    res.status(401).json({ error: error.message });
  }
};
```

**Routes** (`routes/authRoutes.js` - Add to existing file):
```javascript
const { generateQR, verifyQR } = require('../controllers/authController');

router.get('/qr', keycloak.protect(), generateQR);
router.post('/qr/verify', verifyQR);
```

#### Update User Model (`models/User.js`)
```javascript
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema({
  keycloakId: { type: String, unique: true }, // Store Keycloak user ID
  username: { type: String, required: true },
  email: { type: String },
  qrCode: { type: String }, // For QR login
  profilePic: { type: String, default: '' },
  createdAt: { type: Date, default: Date.now }
});

module.exports = mongoose.model('User', userSchema);
```

### Step 4: Sync Users with MongoDB
Keycloak manages users internally, but you may want to sync them with MongoDB for app-specific data:
- Use Keycloak’s Admin REST API or listen to events (e.g., user registration) to update your MongoDB `User` collection.
- Example: After login, check if the user exists in MongoDB and create/update them:
  ```javascript
  router.get('/callback', keycloak.protect(), async (req, res) => {
    const keycloakId = req.kauth.grant.access_token.content.sub;
    const email = req.kauth.grant.access_token.content.email;
    const username = req.kauth.grant.access_token.content.preferred_username;

    let user = await User.findOne({ keycloakId });
    if (!user) {
      user = new User({ keycloakId, username, email });
      await user.save();
    }

    const token = req.kauth.grant.access_token.token;
    res.redirect(`yourapp://auth?token=${token}`);
  });
```

### Step 5: Frontend Integration (Android/iOS)
- **Google/Facebook/Email**: Redirect to `/api/auth/login`, handle the Keycloak login page, and receive the token via `/callback`.
- **QR Code**: Display the QR code from `/qr`, scan it, and send the token to `/qr/verify`.
- Use libraries like `axios` or native HTTP clients to validate tokens with Keycloak’s `/token/introspect` endpoint.

---

### Keycloak vs. Passport.js
- **Keycloak**:
  - Pros: Centralized user management, SSO, prebuilt UI, enterprise-ready.
  - Cons: Requires running a separate server, steeper learning curve.
- **Passport.js**:
  - Pros: Lightweight, fully integrated in Express.js, easier for small projects.
  - Cons: Requires manual implementation for advanced features.

For your TikTok clone, Keycloak is preferable if you anticipate scaling to multiple apps or need advanced IAM features. If simplicity is key, stick with Passport.js.
