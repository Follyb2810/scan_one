To achieve **streaming** and **inability to save videos** as described, you'll need to integrate a cloud storage service (like AWS S3) with your Express.js backend, configure secure video access, and ensure the Android/iOS frontends handle playback correctly. Below, I’ll break down the implementation step-by-step for both the backend and frontend considerations.

---

### 1. Streaming Videos Hosted on AWS S3
#### Backend Setup (Express.js)
You’ll store videos in AWS S3 and generate temporary, signed URLs for secure streaming. Here’s how to implement this:

##### Step 1: Install AWS SDK
```bash
npm install aws-sdk
```

##### Step 2: Configure AWS S3 in Your Backend
Create a file `config/aws.js` to set up AWS credentials:
```javascript
const AWS = require('aws-sdk');

AWS.config.update({
  accessKeyId: process.env.AWS_ACCESS_KEY_ID,
  secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
  region: process.env.AWS_REGION || 'us-east-1',
});

const s3 = new AWS.S3();
module.exports = s3;
```

Update your `.env` file:
```
AWS_ACCESS_KEY_ID=your_access_key
AWS_SECRET_ACCESS_KEY=your_secret_key
AWS_REGION=your_region
S3_BUCKET=your_bucket_name
```

##### Step 3: Modify Video Controller for Upload
In `controllers/videoController.js`, update the `uploadVideo` function to upload to S3:
```javascript
const Video = require('../models/Video');
const s3 = require('../config/aws');
const { v4: uuidv4 } = require('uuid'); // npm install uuid

exports.uploadVideo = async (req, res) => {
  const { userId, description } = req.body;
  const videoFile = req.files?.video; // Assuming you're using multer for file uploads

  if (!videoFile) return res.status(400).json({ message: 'No video file provided' });

  const fileName = `${uuidv4()}-${videoFile.name}`;
  const params = {
    Bucket: process.env.S3_BUCKET,
    Key: fileName,
    Body: videoFile.data,
    ContentType: videoFile.mimetype,
    ACL: 'private', // Ensures the file isn’t publicly accessible
  };

  try {
    const uploadResult = await s3.upload(params).promise();
    const video = new Video({
      userId,
      url: uploadResult.Location, // Full URL (though we’ll use signed URLs for access)
      description,
    });
    await video.save();
    res.status(201).json(video);
  } catch (error) {
    res.status(400).json({ error: error.message });
  }
};
```

Add multer middleware in `app.js` for file uploads:
```javascript
const multer = require('multer');
const upload = multer({ storage: multer.memoryStorage() });

app.use('/api/videos/upload', upload.single('video'), require('./routes/videoRoutes'));
```

##### Step 4: Generate Signed URLs for Streaming
Update `getVideoFeed` to return signed URLs:
```javascript
exports.getVideoFeed = async (req, res) => {
  try {
    const videos = await Video.find().populate('userId', 'username profilePic');
    const videosWithSignedUrls = videos.map(video => {
      const signedUrl = s3.getSignedUrl('getObject', {
        Bucket: process.env.S3_BUCKET,
        Key: video.url.split('/').pop(), // Extract the file key from the URL
        Expires: 3600, // URL expires in 1 hour
      });
      return { ...video._doc, url: signedUrl };
    });
    res.json(videosWithSignedUrls);
  } catch (error) {
    res.status(500).json({ error: error.message });
  }
};
```

#### Frontend Setup (Android/iOS)
- **Android (ExoPlayer)**:
  - Install ExoPlayer in your Android app (`implementation 'com.google.android.exoplayer:exoplayer:2.X.X'`).
  - Use the signed URL to stream the video:
    ```java
    import com.google.android.exoplayer2.SimpleExoPlayer;
    import com.google.android.exoplayer2.source.ProgressiveMediaSource;
    import com.google.android.exoplayer2.upstream.DefaultDataSourceFactory;

    SimpleExoPlayer player = new SimpleExoPlayer.Builder(context).build();
    DefaultDataSourceFactory dataSourceFactory = new DefaultDataSourceFactory(context, "TikTokClone");
    ProgressiveMediaSource mediaSource = new ProgressiveMediaSource.Factory(dataSourceFactory)
        .createMediaSource(Uri.parse(signedUrl));
    player.setMediaSource(mediaSource);
    player.prepare();
    player.setPlayWhenReady(true);
    ```

- **iOS (AVPlayer)**:
  - Use AVPlayer to stream the signed URL:
    ```swift
    import AVKit

    let url = URL(string: signedUrl)!
    let player = AVPlayer(url: url)
    let playerViewController = AVPlayerViewController()
    playerViewController.player = player
    present(playerViewController, animated: true) {
        player.play()
    }
    ```

### 2. Inability to Save Videos
#### Backend: Secure Video Access
- **Signed URLs**: As implemented above, signed URLs expire after a set time (e.g., 1 hour), preventing permanent access. Since the S3 bucket is private, users can’t access videos without a valid signed URL.
- **No Direct Download Links**: The backend never exposes the raw S3 URL; it always provides temporary signed URLs.

#### Frontend: Disable Saving
- **Android (ExoPlayer)**:
  - Disable the download button in the ExoPlayer UI (if using a custom controller):
    ```java
    playerView.setShowBuffering(true);
    playerView.setControllerShowTimeoutMs(0); // Customize controls
    // Avoid adding download functionality to the PlayerControlView
    ```
  - Prevent screen recording programmatically (not foolproof, but adds a layer):
    ```java
    getWindow().setFlags(WindowManager.LayoutParams.FLAG_SECURE, WindowManager.LayoutParams.FLAG_SECURE);
    ```

- **iOS (AVPlayer)**:
  - Disable the default AVPlayerViewController download/share options:
    ```swift
    playerViewController.showsPlaybackControls = true
    playerViewController.allowsPictureInPicturePlayback = false
    // No built-in save option exists, but avoid adding custom save/share buttons
    ```
  - Prevent screen recording (partial protection):
    ```swift
    window?.layer.sublayers?.forEach { $0.isProtectedContent = true }
    ```

#### Additional Security Measures
- **DRM (Digital Rights Management)**: For stronger protection, integrate a DRM solution like Widevine (Android) or FairPlay (iOS) with encrypted video streams. This requires a license server and is more complex but prevents saving even via screen recording.
- **Watermarking**: Overlay user-specific watermarks on videos to discourage unauthorized sharing.

---

### Full Workflow
1. **Upload**: User uploads a video via the app → Backend stores it in S3 → Saves metadata in MongoDB.
2. **Streaming**: App requests video feed → Backend returns signed URLs → Frontend streams using ExoPlayer/AVPlayer.
3. **No Saving**: Signed URLs expire, and frontend disables save options → Videos remain inaccessible offline.

---

### Notes
- **Scalability**: For production, use a CDN (e.g., AWS CloudFront) in front of S3 to reduce latency and improve streaming performance.
- **Authentication**: Secure the `/feed` endpoint with JWT to ensure only authenticated users get signed URLs.
- **Testing**: Test streaming with various network conditions and ensure expiration works as expected.
